# AI use disclosure

RotationLab is a NASA Space Apps 2026 project (challenge: Field Shift: Adapting Farms with NASA Data). This file
is the full statement of how AI was used. Other files point here.

## Summary

- **Code, tests and docs are substantially AI-generated.** AI coding assistants (Claude Code and OpenAI Codex)
  wrote most of the code and tests and the first drafts of the documentation, working from the team's build
  specs and instructions. Every Python file has an `# AI use:` line at the top naming the tool.
- **What the team did.** The team chose the challenge and the problem. It set the scope, the methods and the
  modeling rules through the build specs it gave the assistants, and changed them as the project went on (for
  example, narrowing the app to US farms). It divided the work between members, ran the assistants, reviewed the
  app and its results and asked for corrections, decided what to merge, deployed the app, and prepared the
  demonstration and the submission.
- **Team estimate.** The team estimates that AI assistance accounted for about 30% of the overall project
  effort. This is the team's retrospective estimate across all the work (planning, decisions, review,
  integration, deployment and the demonstration, as well as coding). It was not measured, and it is not a share
  of the code: the file headers and the commit history show that the AI assistants wrote most of the code.
- **No data was generated by AI.**

## Development: which tool did what

- **Claude Code (Anthropic):** the simulation engine and tipping points; the recommendations and "what to check
  first" engine and pages; the US data fetchers (`engine/fetch_nass.py`, `engine/fetch_ers.py`,
  `engine/us_rules.py`); the hindcast and correction code and the trust page; the address lookup
  (`engine/address.py`, `engine/fetch_cdl.py`, `ui/autofill.py`); most tests; and the first drafts of the README,
  LIMITATIONS, DATA_SOURCES, this file and the text in `submission/`.
- **OpenAI Codex:** the app shell and farm setup (`app.py`, `ui/setup.py`, `ui/planner_model.py`, `ui/zones.py`);
  the site and data fetchers (`engine/site.py`, `engine/fetch_soilgrids.py`, `engine/fetch_gibs.py`,
  `engine/climate_card.py`, `engine/zones.py`); parts of `engine/economics.py`; `scripts/precache.py`; their
  tests; the planner styling; and an audit and hardening pass on the API, data and caching.
- **Both tools** also did debugging, later revisions and branch integration under the team's instructions.
- **Earlier version (v3):** built with Claude Code, then debugged and extended with OpenAI Codex. Parts of it are
  still in the repo and keep their headers.

Of the 76 non-merge commits on `main` when this was written (2026-11-15), 71 name an AI assistant as author or
co-author.

## File headers

Every Python file has an `# AI use:` line at the top. It says which tool wrote the file: "written by Claude Code
(Anthropic)", "written with OpenAI Codex", or "written with AI coding assistants (Claude Code and OpenAI Codex)"
where both worked on it, in each case "under the team's direction". A file written with no AI help would say
`# AI use: written by the team without AI assistance. See AI_USE.md.` No file says that today.

## AI inside the app (separate from development)

- The sentence under each recommendation is a fixed template filled in from that card's numbers. No AI writes it.
- Optional: when an `ANTHROPIC_API_KEY` is set, a button can show a short explanation written by Claude
  (`claude-sonnet-5-5`, Anthropic API). Claude is sent computed numbers and crop names only. A guard checks every
  number and crop name in the reply against the input and falls back to the template if any is not there. The
  live app has no key, so it shows the template only. Code: `engine/explain.py`.
- No language model or neural network is part of the crop simulation, the recommendations or the validation.

## Demonstration video

- Every view of the app is a real screen recording.
- The farmland footage at the start and end of the video is generated with Higgsfield, an AI video tool. Those
  segments must carry a visible "SI-generated" label for as long as they are on screen ("SI" is Space Apps' term
  for AI tools). They are illustration. They are not NASA imagery, satellite or field observations, or app output.
- No AI-generated voice or music, no people, and no NASA logos or branding. No AI tool redraws the app's screens
  or numbers.

## What AI did not do

- AI did not make up data. Weather, soil, yield, price and cost values come from the sources in
  `DATA_SOURCES.md` or from the farmer. Values nobody has verified are marked "team to verify" and carry a
  Placeholder or Assumption badge.
- AI-written text is never a model input. Validation uses real yield records, never AI-generated ones. Tests
  that need NASS data use synthetic records, labelled as synthetic in the test files and never used in the app.
- AI help does not show that the model is right for farming. See `LIMITATIONS.md`.
- No NASA endorsement is claimed.
